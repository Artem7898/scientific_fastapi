# Справочник API v1

Базовый URL: `http://localhost:8000/api/v1`. OpenAPI текущего приложения доступен по `/openapi.json`; интерактивные страницы — `/docs` и `/redoc`.

## Каталог научных моделей

`GET /models` возвращает `schema_version`, массив `models` и отдельный массив `backend_availability`. `GET /models/{model_version}` возвращает контракт одной модели; неизвестная версия даёт `404`.

Поддерживаются `ideal-gas-ou-v1`, `langevin-free-v1` и `lennard-jones-2d-v1`. Контракт включает версии, URL приёма, `request_schema`/`result_schema`, единицы, допущения, инварианты с областью применимости, диагностику, обязательные артефакты, возможности оценки неопределённости и правила выбора backend. JSON Schema описывает структуру запроса; межполевые физические ограничения также проверяются Pydantic/domain-валидацией при приёме.

`backends` описывает поддерживаемую семантику модели, а `backend_availability` — только обнаружение зависимости в процессе каталога (`scope="catalog_process"`, `worker_readiness="not_checked"`). Наличие Numba не означает успешный импорт/JIT и не подтверждает её наличие на удалённом worker. Каталог не загружает необязательные вычислительные библиотеки. NumPy остаётся backend по умолчанию; автоматической подмены реализации нет.

Контракт — декларативная, версионированная метаинформация. Его SHA256 идентифицирует конкретный снимок метаданных и схем, а `environment.source_sha256` — реализацию. Номер версии модели сам по себе не запрещает изменение исходного кода: соблюдение политики контролируется review и научными проверками. Изменение научного поведения требует новой версии модели.

## Создать задание

`POST /simulations/monte-carlo`, `Content-Type: application/json`.

Название URL сохранено для совместимости. Расчёт использует модель `ideal-gas-ou-v1`: скорости независимых двумерных частиц с термостатом Орнштейна — Уленбека. Все величины заданы в безразмерных приведённых единицах с `m = k_B = 1`, `γ = 1`.

| Поле | Тип JSON | Ограничение | По умолчанию |
| --- | --- | --- | --- |
| `initial_temperature` | number | конечное, `0 < T <= 1_000_000` | обязательное |
| `num_particles` | integer | `1..1_000_000` | обязательное |
| `time_step` | number | конечное, `0 < dt <= 1_000` | `0.001` |
| `num_steps` | integer | `1..10_000` | `100` |
| `seed` | integer | `0..18_446_744_073_709_551_615` | `0` |
| `backend` | string | только `numpy` или `numba` | `numpy` |

Неизвестные поля, строки вместо чисел, bool вместо integer и нечисловые/бесконечные значения отклоняются. Дополнительно `num_particles * num_steps <= 100_000_000`; оператор может уменьшить бюджет настройками сервера. `initial_temperature` задаёт и начальное распределение, и температуру термостата.

`backend` выбирает реализацию той же OU-модели. Для `numba` установите extra `numba` в API и на всех workers общей очереди; отсутствие зависимости даёт `503` до постановки задания в очередь. Неизвестный backend, включая `jax`, даёт `422`. Ошибка Numba на этапе исполнения не вызывает перехода на NumPy. Выбор сохраняется в задании и используется снова при повторной попытке.

```json
{
  "initial_temperature": 300.0,
  "num_particles": 1000,
  "time_step": 0.001,
  "num_steps": 100,
  "seed": 42
}
```

Успешный приём возвращает **202 Accepted**, а не результат вычисления:

```json
{
  "task_id": "a1b2c3d4",
  "status": "pending",
  "check_url": "/api/v1/simulations/status/a1b2c3d4"
}
```

`task_id` здесь сокращён для примера. Повторная отправка одинакового тела создаёт новое задание; для воспроизводимого результата используйте те же параметры и окружение.

## Создать расчёт координат и переноса

`POST /simulations/langevin`, `Content-Type: application/json`, модель `langevin-free-v1`. Успешный приём также возвращает `202`, `task_id` и прежний `check_url`. Задание использует общие очередь, polling, SSE и отмену.

| Поле | Тип JSON | Ограничение | По умолчанию |
| --- | --- | --- | --- |
| `initial_temperature` | number | конечное, `0.000001..1_000_000` | обязательное |
| `bath_temperature` | number | конечное, `0.000001..1_000_000` | обязательное |
| `num_particles` | integer | `3..1_000_000` | обязательное |
| `mass` | number | конечное, `0.001..1_000` | `1` |
| `friction` | number | скорость релаксации `γ`, `0.001..1_000` | `1` |
| `time_step` | number | конечное, `0.000001..10` | `0.01` |
| `num_steps` | integer | `1..10_000` | `1000` |
| `seed` | integer | `0..18_446_744_073_709_551_615` | `0` |
| `backend` | string | `numpy` или `numba` | `numpy` |
| `initial_mean_velocity` | array из 2 numbers | конечные компоненты, модуль каждой не больше `1000` | `[0, 0]` |
| `initial_position` | array из 2 numbers | начальная точка всех частиц, модуль каждой компоненты не больше `1_000_000` | `[0, 0]` |
| `acceleration` | array из 2 numbers | постоянное ускорение, модуль каждой компоненты не больше `1000` | `[0, 0]` |
| `boundary` | string | `unbounded` или `periodic` | `unbounded` |
| `box_size` | array из 2 numbers или null | каждая длина `0.000001..1_000_000`; обязательна только при `periodic` | `null` |
| `sample_stride` | integer | `1..10_000`, интервал сохранения координат | `10` |
| `diffusion_fit_start_step` | integer или null | `0..num_steps-1` | автоматический выбор |
| `diffusion_fit_end_step` | integer или null | `1..num_steps` | конечный шаг |

Неизвестные поля, нестрогие типы и нечисловые значения отклоняются. Если обе границы подгонки указаны, начало должно предшествовать концу. Сохраняются шаг `0`, кратные `sample_stride` и последний шаг без повтора. Помимо бюджета `N * num_steps <= 100_000_000`, допускается не больше `1001` кадра и `64 MiB` float64-координат формы `(frames, N, 2)`. Превышение даёт `422` до постановки в очередь; увеличьте stride либо уменьшите размер задачи. Сервер может дополнительно снизить вычислительный бюджет.

```json
{
  "initial_temperature": 1.0,
  "bath_temperature": 1.0,
  "num_particles": 1000,
  "time_step": 0.02,
  "num_steps": 1000,
  "seed": 42,
  "acceleration": [0.1, 0.0],
  "boundary": "periodic",
  "box_size": [5.0, 5.0],
  "sample_stride": 10,
  "diffusion_fit_start_step": 500,
  "diffusion_fit_end_step": 1000
}
```

Начальная температура и температура ванны независимы. Ускорение уже включает деление внешней силы на массу. Фрикционный термостат действует в лабораторной системе отсчёта; постоянное ускорение создаёт средний дрейф. Единицы приведённые с `k_B = 1`; модель не калибрует Kelvin, метры или секунды.

## Создать LJ-расчёт взаимодействующих частиц

`POST /simulations/lennard-jones`, `Content-Type: application/json`, модель `lennard-jones-2d-v1`. Приём возвращает `202`, `task_id` и `check_url`; очередь, SSE, отмена и подтверждение попытки общие с другими моделями.

| Поле | Тип JSON | Ограничение | По умолчанию |
| --- | --- | --- | --- |
| `num_particles` | integer | `3..4096` | `64` |
| `box_size` | array из 2 numbers | положительные периодические длины, до `10000*sigma` | `[12, 12]` |
| `initial_temperature` | number | `0.0001..100*epsilon` | `1` |
| `epsilon` | number | `0.001..1000` | `1` |
| `sigma` | number | `0.1..10` | `1` |
| `mass` | number | `0.1..10` | `1` |
| `time_step` | number | от `1e-6` до `0.01` умноженных на `sigma*sqrt(mass/epsilon)` | `0.002` |
| `num_steps` | integer | `1..10000` | `1000` |
| `ensemble` | string | `nve` или `nvt` | `nve` |
| `bath_temperature` | number или null | `0.0001..100*epsilon`, обязательна при NVT; запрещена при NVE | `null` |
| `friction` | number или null | скорость релаксации `0.001..1000`, только NVT | `1` при NVT, иначе `null` |
| `cutoff_radius` | number | `2*sigma..5*sigma` | `2.5` |
| `neighbor_skin` | number | `0.05*sigma..sigma` | `0.3` |
| `interaction_backend` | string | `direct` или `verlet` | `verlet` |
| `backend` | string | `numpy` или `numba` | `numpy` |
| `seed` | integer | unsigned 64-bit | `0` |
| `sample_stride` | integer | `1..10000` | `10` |
| `equilibration_steps` | integer | `0..num_steps-1`, начало описательной production-статистики | `0` |
| `rdf_bins` | integer | `8..256` | `64` |

Все числа конечны, типы строгие, неизвестные поля отклоняются. Требуются `cutoff_radius + neighbor_skin < min(box_size)/2` и шаг исходной решётки не меньше `0.95*sigma`. Изменяя `epsilon`, `sigma` или массу, согласуйте cutoff, skin, бокс и шаг времени с выбранным масштабом. Поле `friction` не включает множитель массы.

```json
{
  "num_particles": 64,
  "box_size": [12.0, 12.0],
  "initial_temperature": 1.0,
  "ensemble": "nvt",
  "bath_temperature": 1.0,
  "friction": 1.0,
  "time_step": 0.002,
  "num_steps": 1000,
  "sample_stride": 10,
  "equilibration_steps": 500,
  "seed": 42,
  "interaction_backend": "verlet"
}
```

NVE использует velocity Verlet, NVT — BAOAB с точным OU-подшагом. Потенциал и сила имеют согласованную shifted-force обрезку; хвостовые поправки и внешние поля в этот контракт не входят. Единицы приведённые с `k_B=1`. Инициализация фиксирует кинетическую температуру после удаления скорости центра масс и не считается каноническим равновесием.

До приёма проверяются `N*steps <= 20_000_000`, не больше `1001` кадра и `64 MiB` координатной траектории. Прямой алгоритм дополнительно требует `(steps+2)*N*(N-1)/2 <= 100_000_000`: учтены начальная сила, силы шагов и конечный RDF. Во время исполнения действует общий бюджет проверок пар, включая поиск соседей и анализ; его исчерпание завершается явной ошибкой задания. `backend="numba"` требует extra на API и каждом consumer, как у прежних моделей.

## Получить статус или результат

`GET /simulations/status/{task_id}` возвращает **200 OK** для известного задания. Ответ представляет одно из состояний:

| `status` | Значение |
| --- | --- |
| `pending` | задание принято и ожидает вычислителя |
| `running` | вычисление началось |
| `completed` | расчёт и сохранение результата завершены |
| `failed` | вычисление или необходимая инфраструктурная операция завершилась ошибкой |
| `cancelled` | выполнение прекращено |

Минимальный ожидающий ответ:

```json
{"task_id":"a1b2c3d4","status":"pending"}
```

Завершённый ответ содержит следующие научные поля; значения ниже приведены только как пример формата:

```json
{
  "task_id": "a1b2c3d4",
  "status": "completed",
  "attempt_id": "9e108b11-42b2-4d92-a66d-ec07708c8d75",
  "final_temperature": 299.5,
  "total_energy": 299500.0,
  "temperature_standard_error": 9.486832980505138,
  "model_version": "ideal-gas-ou-v1",
  "seed": 42,
  "num_steps": 100,
  "units": {"temperature": "reduced", "energy": "reduced", "time": "reduced"},
  "artifacts": {
    "manifest": "a1b2c3d4/9e108b11-42b2-4d92-a66d-ec07708c8d75/manifest.json",
    "final_state": "a1b2c3d4/9e108b11-42b2-4d92-a66d-ec07708c8d75/final_state.npz"
  }
}
```

`task_id` остаётся одним и тем же после повторного исполнения задания. `attempt_id` — UUID конкретной подтверждённой попытки, завершившей расчёт. Ссылки в `artifacts` относительны к `ARTIFACTS_DIR` сервера и включают оба ID, чтобы запоздавшие вычислители не перезаписали опубликованные файлы. Manifest содержит входы, результаты, модель, RNG, окружение и SHA256 конечного состояния; `final_state.npz` содержит массив `velocities` типа `float64`, формы `(num_particles, 2)`. Для работы на нескольких машинах каталог артефактов должен быть общим.

В новых manifest раздел `execution` содержит `backend`, `backend_version`, `kernel_version`, `device`, `dtype`, `fastmath`, `parallel`, `rng_policy` и `observables_schedule`; Numba также фиксирует `nogil` и отключённый дисковый кеш. Обе реализации используют CPU, float64 и NumPy PCG64; межbackend-сравнение требует численного допуска. Формат ответа polling остаётся прежним, а точные сведения об исполнении доступны в manifest. Ранее сохранённые NumPy-результаты без `execution` продолжают поддерживаться.

`temperature_standard_error = initial_temperature / sqrt(num_particles)` — теоретическая стандартная ошибка температуры по конечному снимку в данной модели. Это не доверительный интервал и не оценка неопределённости реального эксперимента.

Ошибки задания возвращаются через терминальное состояние `failed`; успешный GET статуса сам по себе не означает успешный расчёт. Клиент должен проверять `status`, прекращать polling в терминальном состоянии и использовать разумный интервал повторов.

### Результат `langevin-free-v1`

Общие поля `task_id`, `attempt_id`, `status`, `seed`, `num_steps`, `units` сохраняются. Поле `model_version` различает научные контракты завершённого ответа:

| Поле новой модели | Содержание |
| --- | --- |
| `thermal_temperature` | `m * sum(|v_i-mean(v)|²) / (2*(N-1))`, тепловая температура без среднего потока |
| `thermal_temperature_standard_error` | теоретическая ошибка `T_v(t)/sqrt(N-1)`, где `T_v(t)=T_b+(T_0-T_b)exp(-2γt)` |
| `kinetic_energy` | `m/2 * sum(|v_i|²)`, включает энергию среднего потока |
| `mean_velocity` | две компоненты средней конечной скорости |
| `mean_displacement` | две компоненты среднего непрерывного смещения от начальной точки |
| `final_msd` | среднее квадрата полного смещения, включая дрейф |
| `final_centered_msd` | сумма квадратов отклонений смещения от среднего, делённая на `N-1` |
| `diffusion` | статус, оценка, стандартная ошибка, теория и методика выбранного окна |
| `artifacts` | относительные пути `manifest`, `final_state`, `trajectory`, `transport` подтверждённой попытки |

Подгонка диффузии использует OLS центрированного MSD по времени со свободным членом; `estimate = slope/4`. Нужны как минимум три сохранённых точки и затухание начального переходного процесса. Минимум — пять времён релаксации, с более поздней границей при сильном различии температур. Аналитическая относительная ошибка того же окна должна быть не больше `1%`. Если условия не выполнены, `diffusion.status="unavailable"`, `estimate` и `standard_error` равны `null`, а `reason` объясняет причину. Сам расчёт остаётся успешным и сохраняет траекторию. Доступная шумная оценка может быть отрицательной и не обрезается до нуля.

Стандартная ошибка доступной оценки рассчитывается delete-one-particle jackknife: исключается вся траектория частицы, а не один коррелированный временной кадр. Она не является доверительным интервалом, не включает смещение конечного окна и не проверяет правильность иной физической модели. Подробная теория, выбор окна и массивы MSD находятся в `transport.json`.

### Результат `lennard-jones-2d-v1`

Общие поля task/attempt/seed/status/steps сохраняются; `model_version` выбирает отдельный контракт результата:

| Поле | Содержание |
| --- | --- |
| `ensemble` | `nve` или `nvt` |
| `thermal_temperature` | `m * sum(|v_i-mean(v)|²) / (2*(N-1))` |
| `kinetic_energy` | полная кинетическая энергия, неотрицательная |
| `potential_energy` | сумма shifted-force парных потенциалов, знаковая |
| `total_energy` | `kinetic_energy + potential_energy`, знаковая |
| `pressure` | механическое давление `(2K+W)/(2A)`, знаковое |
| `diagnostics` | фактические проверки пар сил/поиска/RDF, перестроения соседей и бюджет |
| `artifacts` | `manifest`, `final_state`, `trajectory`, `observables` |

`observables.json` содержит ряды всех энергий, температуры, давления и virial, описательные средние/SD production-кадров, диагностику изменения энергии и RDF конечного снимка. Отрицательные энергия и давление допустимы и не заменяются нулём. Для NVT изменение полной энергии отражает обмен с термостатом; формула стандартной ошибки независимого OU-снимка и свободная теория диффузии здесь не применяются.

## Прогресс через SSE

`GET /simulations/{task_id}/events` возвращает **200 OK**, `Content-Type: text/event-stream`. Поток наблюдает существующее задание и не запускает новую симуляцию; обычный GET статуса сохраняет прежний контракт.

```bash
curl -N http://localhost:8000/api/v1/simulations/TASK_ID/events
```

Пример кадра; `id` ниже иллюстрирует формат, а не действующий cursor:

```text
id: 1710000000000-0
event: progress
data: {"task_id":"a1b2c3d4","status":"running","phase":"computing","attempt":1,"completed_steps":40,"total_steps":100}

```

`attempt` — счётчик попыток исполнения. UUID `attempt_id` подтверждённого результата доступен в завершённом статусе и артефактах. При новой попытке счётчик увеличивается, шаги начинаются заново. Значение `completed_steps == total_steps` может соответствовать фазе `saving_artifacts` со статусом `running`; дожидайтесь терминального статуса, а не только достижения последнего шага.

| SSE event | Значение |
| --- | --- |
| `progress` | снимок статуса, фазы и выполненных шагов текущей попытки |
| `reset` | переданный cursor отсутствует в доступной истории; данные содержат актуальный снимок |
| `expired` | запись исчезла во время открытого потока; соединение закрывается |
| `error` | backend стал недоступен во время открытого потока; соединение закрывается |

После терминального снимка (`completed`, `failed`, `cancelled`) сервер закрывает поток. При отсутствии обновлений отправляется комментарий `: keep-alive` примерно каждые 15 секунд. После открытия ошибки передаются SSE-кадрами: HTTP-код уже остаётся `200`. Неизвестный/истёкший ID до открытия даёт `404`, недоступный backend — `503`.

Для переподключения передайте **реальный последний полученный `id`** в заголовке `Last-Event-ID`. Он имеет формат двух неотрицательных целых через дефис, длину до 64 символов; синтаксически неверный заголовок даёт `422`. Пример команды с cursor:

```bash
curl -N -H 'Last-Event-ID: 1710000000000-0' \
  http://localhost:8000/api/v1/simulations/TASK_ID/events
```

Без cursor передаётся доступная история; сохраняются последние 256 событий задания. Если cursor уже удалён или неизвестен, обработайте `reset` как замену локального снимка и продолжайте с новым `id`. Не считайте такой replay полной историей и допускайте повторную доставку снимков. Отдельного checkpoint для продолжения вычисления нет.

Число одновременных SSE-соединений ограничено `SSE_MAX_CONNECTIONS` на процесс API, по умолчанию `32`. При занятости ответ — `429` с `Retry-After: 1`. Разрыв SSE-соединения освобождает место для наблюдателя, но не отменяет симуляцию. Запросы backend для обновления потока выполняются с `EVENT_POLL_INTERVAL_SECONDS`, по умолчанию `0.25` секунды. Это не гарантированная частота публикации каждого вычислительного шага.

## Отменить задание

`POST /simulations/{task_id}/cancel` возвращает **202 Accepted** и заголовок `Location` с прежним URL статуса:

```json
{"task_id":"a1b2c3d4","status":"cancellation_requested"}
```

```bash
curl -X POST http://localhost:8000/api/v1/simulations/TASK_ID/cancel
```

Это подтверждение запроса, а не гарантия немедленной остановки потока. Проверьте окончательный статус через polling или SSE. Отмена уже `completed`/`failed` задания даёт `409`; повтор для `cancelled` допускается и возвращает тот же формат подтверждения. Неизвестное или истёкшее задание даёт `404`.

## Создать ансамбль независимых повторов

`POST /ensembles`, `Content-Type: application/json`. Ансамбль создаёт дочерние задания через существующую очередь и не создаёт отдельный пул из одного потока на повтор.

| Поле | Тип JSON | Ограничение | По умолчанию |
| --- | --- | --- | --- |
| `model` | string | `ideal-gas-ou-v1`, `langevin-free-v1` или `lennard-jones-2d-v1` | `ideal-gas-ou-v1` |
| `parameters` | object | параметры выбранной модели без `seed`; типы разных моделей не смешиваются | обязательное |
| `replicas` | integer | `1..50`, строгий тип | `50` |
| `base_seed` | integer | `0..18_446_744_073_709_551_615`, строгий тип | `0` |
| `failure_policy` | string | только `require_all` | `require_all` |

В `parameters` доступны `initial_temperature`, `num_particles`, `time_step`, `num_steps` и `backend` с теми же диапазонами и значениями по умолчанию, что у одиночной симуляции. `parameters.backend="numba"` выбирает Numba для всех реплик и требует установленного extra; отсутствие Numba отклоняет весь запрос с `503` до приёма детей. `parameters.seed` и неизвестные поля отклоняются. Бюджет — **`replicas * num_particles * num_steps <= MAX_PARTICLE_STEPS`**, не более `100_000_000`; серверный предел числа шагов также действует.

```bash
curl -X POST http://localhost:8000/api/v1/ensembles \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: temperature-study-001' \
  -d '{"model":"ideal-gas-ou-v1","parameters":{"initial_temperature":300.0,"num_particles":1000,"time_step":0.001,"num_steps":100},"replicas":4,"base_seed":42,"failure_policy":"require_all"}'
```

До начала выполнения сохраняются все task ID и фактические uint64 seed. Они получаются через `numpy.random.SeedSequence(base_seed).spawn(replicas)` и `generate_state`, а не как `base_seed + index`. Manifest сохраняет seed, порядок реплик и описание этой политики с версией NumPy. Каждая дочерняя симуляция использует свой PCG64.

Общий бюджет — `replicas * num_particles * num_steps <= 100_000_000`, с возможным снижением сервером. Для `langevin-free-v1` также действует `frames * N * 2 * 8 * replicas <= 512 MiB` несжатых координат всех траекторий. Лимиты одной реплики `64 MiB` и `1001` кадр сохраняются. Превышение бюджета даёт `422` до приёма; ограничение координат не описывает размер сжатых файлов или полный RSS workers.

Приём резервирует ёмкость **для всех** дочерних заданий атомарно. Если свободной ёмкости недостаточно, ответ — `429` с `Retry-After: 1`, без частично принятого ансамбля. Успех возвращает **202 Accepted**, `Location` и `Retry-After: 1`:

```json
{"ensemble_id":"b1c2d3e4","status":"pending","check_url":"/api/v1/ensembles/b1c2d3e4"}
```

Необязательный `Idempotency-Key` допускает `1..128` символов. Повтор с тем же ключом и теми же валидированными параметрами возвращает тот же `ensemble_id`, не создавая новые задания и не занимая дополнительную ёмкость. Другие параметры с тем же ключом дают `409`. Ключ действует, пока сохранена родительская запись; это не бессрочная дедупликация. Без ключа каждый POST создаёт новый ансамбль.

Явный `backend="numpy"` эквивалентен отсутствующему полю, в том числе при повторе запроса ансамбля, принятого до появления выбора backend. Замена NumPy на Numba с тем же ключом — изменение параметров и даёт `409`.

## Статус, отмена и manifest ансамбля

| Метод и URL | Результат |
| --- | --- |
| `GET /ensembles/{ensemble_id}` | `200`, состояние ансамбля и всех дочерних заданий |
| `POST /ensembles/{ensemble_id}/cancel` | `202`, `{"ensemble_id":"...","status":"cancel_requested"}`; окончательное состояние уточняется polling |
| `GET /ensembles/{ensemble_id}/manifest` | `200`, JSON для скачивания после завершения всех реплик; до этого `409` |

```bash
curl http://localhost:8000/api/v1/ensembles/ENSEMBLE_ID
curl -X POST http://localhost:8000/api/v1/ensembles/ENSEMBLE_ID/cancel
curl -o ensemble-manifest.json http://localhost:8000/api/v1/ensembles/ENSEMBLE_ID/manifest
```

Состояние содержит `ensemble_id`, `status`, `cancel_requested`, `model`, `failure_policy` и следующие данные:

| Поле | Содержание |
| --- | --- |
| `counts` | `requested`, `pending`, `running`, `completed`, `failed`, `cancelled` |
| `children` | записи в порядке `replica_index`: `task_id`, фактический `seed`, `status`, подтверждённый `result` либо `null` |
| `statistics` | агрегаты выбранной модели только при успехе **всех** повторов, иначе `null` |
| `theoretical_temperature_standard_error` | для старой модели `T / sqrt(N * M)`, для новой `T_v(t)/sqrt((N-1)*M)`; иначе `null` |

У `ideal-gas-ou-v1` агрегируются `final_temperature` и `total_energy`. У `langevin-free-v1` — `thermal_temperature`, `kinetic_energy` и `final_centered_msd`; `diffusion_estimate` добавляется только при доступной оценке диффузии во всех репликах. Межповторная SD/SE оценки диффузии отличается от её jackknife-ошибки внутри одной реплики.

Для `lennard-jones-2d-v1` агрегируются `thermal_temperature`, `kinetic_energy`, `potential_energy`, `total_energy` и `pressure`; `theoretical_temperature_standard_error` равна `null`. В запросе укажите LJ-модель и её параметры без `seed`. Помимо общих ограничений, суммарная координатная траектория не превышает `512 MiB`, суммарная работа `N*steps*replicas` — `20_000_000`, а для прямого варианта сумма попарной работы — `100_000_000`. SD/SE относятся к независимым репликам; коррелированные временные кадры отдельного расчёта не подменяют их.

Пока остались незавершённые реплики, родитель имеет `pending` или `running`. Когда все реплики терминальны, наличие хотя бы одной ошибки даёт `failed`, иначе наличие отменённых — `cancelled`, иначе `completed`. `require_all` не скрывает неуспешные повторы и не агрегирует только выжившие. Отмена терминального ансамбля даёт `409`; неизвестная или истёкшая запись — `404`.

Каждая статистика содержит `n`, `mean`, `sample_standard_deviation` и `standard_error`. При всех успешных `M >= 2` выборочное SD использует `ddof=1`, а SE равно `SD / sqrt(M)`. При `M=1` среднее доступно, но SD и SE равны `null`. Это эмпирическая неопределённость среднего **между независимыми повторами**; она отличается от теоретической ошибки одного снимка `T/sqrt(N)` и не означает доверительный интервал или валидацию физической модели.

Родитель сохраняет терминальные вклады детей независимо от их временных статусов. Пока родительская запись доступна, истечение отдельного детского статуса не удаляет уже записанный вклад из агрегата и manifest. Успешный `result` сохраняет `task_id`, `attempt_id` и ссылки на артефакты подтверждённой попытки; ошибки и отмены остаются явными результатами. Дочерний task ID можно использовать с прежними API статуса, SSE, отмены и анализа снимка, пока доступна его запись.

Терминальный manifest содержит запрос, fingerprint, фактические seed, политику их получения, результаты каждой реплики и метод агрегирования. Это JSON-снимок родительской записи, который следует скачать для длительного хранения; файлы исходных симуляций он не включает. После терминального завершения родитель и idempotency-запись хранятся в пределах `TASK_TTL_SECONDS`. Redis сохраняет их через перезапуск; режим памяти — нет. Самостоятельных SSE-потоков ансамблей этот контракт не добавляет: наблюдайте родителя через GET и при необходимости потоки дочерних заданий.

## Прочитать Result Envelope

```text
GET /simulations/{task_id}/envelope
GET /simulations/{task_id}/analyses/{analysis_id}/envelope
```

Оба маршрута требуют доступного статуса `completed` исходной симуляции. Они возвращают типизированный конверт с `schema_version=1`, `kind` (`simulation` или `velocity_analysis`), идентификаторами задачи/попытки/анализа и исходным `result`. В конверт также входят:

- `model_contract`: версия модели, версия схемы контракта, сохранённый `snapshot` и его SHA256;
- `manifest`: путь, SHA256 точных байтов и размер исходного manifest;
- `artifacts`: пути, размеры, MIME-типы и контрольные суммы обязательных файлов;
- `parameters`, `execution`, `rng`, `environment`, `diagnostics` и `units`;
- `uncertainty`: доступность оценки, её описание и явная причина отсутствия;
- `integrity`: состояние проверки и её область `saved_metadata_and_bytes`;
- `authenticity="unsigned"` и `scientific_verification="not_performed"`.

После записи артефактов новый расчёт записывает manifest с объявлением `result_envelope={"schema_version":1,"path":"TASK_ID/ATTEMPT_ID/envelope.json"}`, затем отдельный `envelope.json`. Для анализа путь содержит также `analyses/ANALYSIS_ID`. Конверт хранит digest manifest; manifest не хранит digest конверта, что исключает рекурсивное хеширование. До успешной публикации и проверки конверта новый расчёт не подтверждается как успешный. Прежние ответы polling, имена артефактов и `manifest.outputs` сохраняются.

Endpoint заново читает manifest и проверяет контрольные суммы файлов, принадлежность попытке, состав артефактов и связь с исходным результатом. Ранее записанное `integrity.status="verified"` не заменяет эту проверку. Ответ имеет `Cache-Control: no-store`: он описывает файлы, проверенные данным запросом. Проверка не перезапускает физику и не проверяет численную реализацию независимо.

Снимок контракта проверяется относительно записанного digest, а не заменяется текущим ответом каталога. Поэтому изменение описательных метаданных каталога не переписывает доказательства старого запуска. Архивирование снимка не гарантирует, что любая будущая версия пакета сможет прочитать любой старый формат: изменения схем требуют явной политики совместимости.

Если manifest не объявляет конверт и конверт отсутствует, ответ явно содержит `integrity.status="not_verified"` и `reason="envelope_not_recorded"`; недостающие сведения не выдумываются. Если конверт объявлен, но отсутствует, повреждён или не согласован с файлами, возвращается `409` с машиночитаемым `detail.code`. Для незавершённого задания используется `RESULT_NOT_COMPLETED`; неизвестный анализ даёт `404` и `ANALYSIS_NOT_FOUND`. Ошибка доступа к инфраструктуре может дать `503` и `EVIDENCE_STORAGE_UNAVAILABLE`. API не раскрывает пути сервера или внутренние тексты исключений.

Целостность проверяется относительно сохранённых метаданных в том же хранилище. Одновременная подмена всех файлов и метаданных не обнаруживается как нарушение авторства: подписи и отдельного доверенного журнала на этом этапе нет. Конверт не является сертификатом научной корректности. Для LJ отсутствие независимой ошибки коррелированных рядов отмечается явно; текущие описательные SD не преобразуются в доверительный интервал.

HTTP-доступ по этим маршрутам, как и по прежним URL артефактов, зависит от доступности записи задачи в пределах TTL. Сохранённые файлы можно проверять напрямую из Python независимо от срока жизни HTTP-статуса; пример приведён в [руководстве разработки](development.md).

## Скачать артефакты

`GET /simulations/{task_id}/artifacts/{artifact_name}` возвращает файл из подтверждённой попытки завершённого задания. Передавать `attempt_id` в этот URL не требуется. У `ideal-gas-ou-v1` допустимы `manifest` и `final_state`; у `langevin-free-v1` также `trajectory` и `transport`; у `lennard-jones-2d-v1` — `manifest`, `final_state`, `trajectory`, `observables`. Это фиксированные имена, а не произвольные пути:

```bash
curl -o manifest.json http://localhost:8000/api/v1/simulations/TASK_ID/artifacts/manifest
curl -o final_state.npz http://localhost:8000/api/v1/simulations/TASK_ID/artifacts/final_state
```

Для ещё исполняемого задания ответ — `409 Conflict`, для неизвестного задания или отсутствующего файла — `404`. Срок хранения статуса и файлов управляется отдельно; сохраните нужные артефакты до истечения срока доступности задания.

Для `langevin-free-v1` файлы имеют следующий состав:

| Имя | Файл | Содержание |
| --- | --- | --- |
| `manifest` | `manifest.json` | модель, входы, наблюдаемые, sampling, неопределённость и SHA256 файлов |
| `final_state` | `final_state.npz` | `positions`, `unwrapped_positions`, `velocities`, float64 `(N, 2)` |
| `trajectory` | `trajectory.npz` | `positions`: непрерывные координаты float64 `(frames, N, 2)`; `sample_steps`: int64; `times`: float64 |
| `transport` | `transport.json` | средние смещения, MSD, центрированное MSD, аналитические кривые и оценивание диффузии |

В периодической области конечный `positions` обёрнут в бокс, но `unwrapped_positions` и массив `positions` в траектории всегда непрерывны. Для анализа MSD используйте именно траекторию. Артефакты исходного расчёта не являются checkpoint для продолжения RNG/симуляции.

У LJ-модели `final_state.npz` содержит `positions`, `unwrapped_positions` и `velocities`; `trajectory.npz` — непрерывные `positions`, int64 `sample_steps` и float64 `times`. Вместо `transport.json` сохраняется `observables.json`: `series`, `production`, `energy_drift` и `rdf`. Доступ к `transport` у LJ и к `observables` у прежних моделей даёт `404`. RDF нормирован на двумерные площади колец и `N(N-1)/2` уникальных пар; он относится к одному конечному снимку, а не к независимой временной выборке.

## Создать анализ сохранённых скоростей

`POST /simulations/{task_id}/analyses`, `Content-Type: application/json`. Этот анализ Гаусса/Рэлея принимает только `ideal-gas-ou-v1`; Langevin использует `transport.json`, LJ — `observables.json`. Несовместимая модель даёт `409`, без повторного запуска физики и без подмены теории.

Анализ использует `final_state.npz` **подтверждённой попытки** задания со статусом `completed`. Перед чтением проверяются связь manifest с результатом, `task_id` и `attempt_id`, SHA256 состояния, форма и конечность массива скоростей и совместимость с моделью `ideal-gas-ou-v1`. Новая симуляция не запускается.

| Поле | Тип JSON | Ограничение | По умолчанию |
| --- | --- | --- | --- |
| `bins` | integer | `2..256`, без bool и преобразования строк | `32` |
| `formats` | array of string | только `png` и `pdf`, без повторов | `[]` |

Неизвестные поля отклоняются. `formats: []` создаёт только JSON и работает без Matplotlib. PNG и PDF создаются только при явном указании соответствующего формата и требуют extra `research`.

```bash
curl -X POST http://localhost:8000/api/v1/simulations/TASK_ID/analyses \
  -H 'Content-Type: application/json' \
  -d '{"bins":32,"formats":[]}'
```

Генерация выполняется в ограниченном пуле потоков; HTTP-запрос **ожидает её завершения**. Успех возвращает **201 Created**. Заголовок `Location` содержит URL manifest анализа. Пример JSON-ответа:

```json
{
  "analysis_id": "0123456789abcdef0123456789abcdef",
  "task_id": "a1b2c3d4",
  "attempt_id": "9e108b11-42b2-4d92-a66d-ec07708c8d75",
  "status": "completed",
  "analysis_version": "velocity-distribution-v1",
  "artifacts": {
    "analysis": "/api/v1/simulations/a1b2c3d4/analyses/0123456789abcdef0123456789abcdef/artifacts/analysis",
    "manifest": "/api/v1/simulations/a1b2c3d4/analyses/0123456789abcdef0123456789abcdef/artifacts/manifest"
  }
}
```

В отличие от относительных файловых путей результата симуляции, значения `artifacts` анализа — URL API. При `formats: ["png", "pdf"]` ответ дополнительно содержит ключи `png` и `pdf` с URL скачивания. `analysis_id` создаётся заново при каждом успешном POST; одинаковый запрос не возвращает ранее созданный анализ.

JSON `analysis` содержит размер выборки, моменты компонент и скорости, оценку температуры, гистограммы `vx`/`vy`/`speed`, теоретические значения и ограничения интерпретации. Компоненты сравниваются с `Normal(0, T)`, модуль скорости — с распределением Рэлея, то есть двумерным распределением Максвелла — Больцмана. Здесь `T` — заданная температура модели, а не значение, подогнанное по снимку; дисперсии рассчитываются с `ddof=0`.

`theoretical_density` — средняя теоретическая плотность внутри каждого бина, вычисленная из разности CDF. Теория не перенормируется на наблюдаемый диапазон: `theoretical_coverage` и `theoretical_missing_mass` показывают попавшую и не попавшую в него массу вероятности. PNG содержит три панели распределений, PDF — график, описание исходного расчёта и ограничения. Моменты и визуальное согласие не дают p-value и не доказывают корректность модели или достижение равновесия; исходная OU-модель уже начинается в равновесном распределении.

По умолчанию одновременно выполняются не более двух анализов **на процесс API**. `ANALYSIS_WORKER_COUNT` допускает `1..8`. Если слоты заняты, сервер сразу отвечает `429 Too Many Requests` с `Retry-After: 1`. Анализы не поступают в постоянную очередь симуляций и не имеют отдельного polling-контракта с `202`. При разрыве HTTP-соединения вычислительный поток продолжает работу; слот освобождается после фактического завершения. Клиент может не получить URL результата. Повторный POST создаёт отдельный анализ: идемпотентность и восстановление такого запроса на этом этапе не предусмотрены.

## Скачать артефакты анализа

`GET /simulations/{task_id}/analyses/{analysis_id}/artifacts/{artifact_name}` возвращает **200 OK** и файл подтверждённой попытки. Допустимы следующие имена:

| `artifact_name` | Файл | Content-Type |
| --- | --- | --- |
| `analysis` | `analysis.json` | `application/json` |
| `manifest` | `manifest.json` | `application/json` |
| `png` | `velocity_distribution.png` | `image/png` |
| `pdf` | `report.pdf` | `application/pdf` |

```bash
curl -o analysis.json http://localhost:8000/api/v1/simulations/TASK_ID/analyses/ANALYSIS_ID/artifacts/analysis
curl -o analysis-manifest.json http://localhost:8000/api/v1/simulations/TASK_ID/analyses/ANALYSIS_ID/artifacts/manifest
curl -o velocity_distribution.png http://localhost:8000/api/v1/simulations/TASK_ID/analyses/ANALYSIS_ID/artifacts/png
curl -o report.pdf http://localhost:8000/api/v1/simulations/TASK_ID/analyses/ANALYSIS_ID/artifacts/pdf
```

PNG/PDF доступны только если соответствующий формат был запрошен при генерации. Manifest анализа связывает `analysis_id`, версию анализа, параметры, исходную попытку и SHA256 её состояния и manifest, окружение, а также хеши созданных JSON/PNG/PDF. При скачивании проверяется принадлежность текущей подтверждённой попытке; для `analysis`, `png` и `pdf` дополнительно сверяется SHA256 с manifest анализа.

Каталог хранения: `ARTIFACTS_DIR/<task_id>/<attempt_id>/analyses/<analysis_id>/`. Доступ через API требует сохранённого статуса исходного задания: после его истечения согласно `TASK_TTL_SECONDS` ответ — `404`, даже если файлы остались на диске. Файлы анализа автоматически по этому TTL не удаляются; скачивание и очистку нужных данных планируйте отдельно.

Для интерактивного сценария откройте `/docs`, в группе **Scientific Analysis** выполните POST через **Try it out → Execute** и откройте URL из `artifacts` ответа. Существующие URL создания симуляции, polling и скачивания её исходных артефактов сохраняют свой контракт.

## HTTP-ошибки

| Код | Когда возникает |
| --- | --- |
| `422` | неверные типы, неизвестные поля, нечисловые величины, превышение диапазонов или бюджета запроса; для анализа также повторы или неизвестные значения `formats` |
| `404` | задание или ансамбль неизвестны/истекли, анализ/артефакт отсутствует или скачиваемый файл анализа не проходит проверку |
| `409` | исходный расчёт ещё не завершён; повреждённые или несовместимые исходные артефакты анализа; конфликт `Idempotency-Key`; manifest ансамбля до завершения или отмена уже завершённой работы |
| `429` | очередь симуляций заполнена, заняты слоты анализа/SSE либо недостаточно ёмкости для целого ансамбля; заголовок `Retry-After: 1` |
| `503` | приложение останавливается или инфраструктура недоступна; при выбранном Numba отсутствует extra `numba`; при запросе PNG/PDF отсутствует extra `research` |
| `500` | непредвиденная ошибка генерации анализа; подробности в журнале сервера |

## Проверки состояния

Эти URL не имеют префикса `/api/v1`:

- `GET /health/live` — процесс приложения работает.
- `GET /health/ready` — приложение готово обслуживать запросы с текущими ресурсами. При неготовности возможен `503`.

Готовность сервиса не доказывает научную корректность произвольного входа; модель и её ограничения описаны в [архитектуре](architecture.md).
